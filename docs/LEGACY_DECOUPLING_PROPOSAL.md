# 提案：新舊系統完全隔離計畫 (Zero Data Loss)

您絕對是對的，**「資料最重要，先求有再求好」**。
以下這份提案的最高原則是：**絕對不會刪除任何現有資料**。我們透過「複製 (Copy)」而非「搬移 (Move)」來達成兩套系統的完全獨立。

## 當前狀態釐清
*   **新系統 (TCMS)**：資料放在 `tcms_users` 等表裡（共有 11 筆）。
*   **舊系統 (Legacy)**：目前透過 View (捷徑) 讀取 `tcms_users`。兩套系統目前共用同一桶水。

## 目標
打破這個 View (捷徑)，讓舊系統擁有自己專屬的 `users` 實體水桶，且裡面裝滿目前的資料。修改新系統不會影響舊系統，反之亦然。

---

## 實作步驟 (保證資料不遺失)

### 步驟零：執行全量備份 (買保險)
在做任何動作前，我們會先執行剛剛寫好的 `/data/docker-postgres/scripts/db_backup.sh`，將目前「完美可用」的狀態鎖定備份下來。

### 步驟一：處理 15 張核心表（解除共用並複製資料）
對於每一個有 View 的表（例如 `users`）：
1.  執行 `DROP VIEW users;`
    *   *(說明：請放心，這只是刪除「捷徑名稱」，**絕對不會**刪除 `tcms_users` 裡面的 11 筆真實資料。)*
2.  執行 `CREATE TABLE users AS SELECT * FROM tcms_users;`
    *   *(說明：這會立刻建立一張真實獨立的 `users` 實體表，同時把 `tcms_users` 裡的那 11 筆資料**複製**過去給它。)*
3.  **結果**：舊系統有了完全獨立的 `users` 表與資料，新系統繼續用 `tcms_users`。兩者從此各走各的路，互不影響。

### 步驟二：確認現有自動化表（不更動資料）
您提到的 13 張自動化表（如 `automation_auth` 等）因為**已經有倒回資料**，所以我們**完全不動它們**，保持現狀。

---

## 預期成果
執行完這份提案後：
1. **新系統**：不受任何影響，繼續使用 `tcms_` 表。
2. **舊系統**：擁有自己最初的獨立實體表（15 張從現在的 `tcms_` 完整複製出來，其他非 tcms 開頭的表保持原樣不動）。
3. **兩不相干**：未來的開發與測試，兩邊系統完全資料隔離，互不干擾。
