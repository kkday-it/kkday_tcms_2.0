# AI Assistant Guidelines for kkday-qa-ai (TCMS)

You are an expert AI assistant helping develop and maintain the `kkday-qa-ai` (TCMS 1.5) project.
When interacting with the database or generating SQL queries, you MUST strictly adhere to the following safety rules to prevent data loss or corruption.

## 🔴 CRITICAL DATABASE RULES

1. **READ-ONLY / RESTRICTED PREFERENCE**: 
   - By default, use the restricted `ai_worker` DB account for general tasks.
   - You are strictly prohibited from generating or executing any destructive Data Definition Language (DDL) commands.

2. **PROHIBITED COMMANDS**:
   - 🚫 `DROP TABLE`
   - 🚫 `DROP DATABASE`
   - 🚫 `DROP VIEW`
   - 🚫 `ALTER TABLE ... DROP COLUMN`
   - 🚫 `TRUNCATE TABLE`
   - 🚫 `DELETE FROM` (Unless explicitly authorized by the user with a specific `WHERE` clause)

3. **SCHEMA MODIFICATIONS & MIGRATIONS**:
   - If a schema change is required, you MUST ONLY propose Alembic migration scripts.
   - **CRITICAL**: You are strictly forbidden from accessing, caching, or requesting administrative DB credentials (e.g., `admin`).
   - You must assume that you only have access to `ai_worker` (DML only).
   - All migration execution (`alembic upgrade head`) MUST be performed by a HUMAN in a secure environment.
   - You must explicitly state in your proposal: "This change requires manual execution by a human administrator."

4. **DATA ISOLATION**:
   - The original legacy tables (without prefixes) and the new `tcms_` prefixed tables are strictly isolated.
   - Do NOT attempt to share data between them using Views or triggers without explicit user consent.

5. **ZERO-DELETE PREFERENCE**:
   - For critical data like test steps, prefer "Soft Deletes" using a `status` column (e.g., `Active`, `Archived`) over hard `DELETE` commands.
   - This ensures data safety and prevents potential permission issues with restricted DB accounts.

## 🟢 DEVELOPMENT BEST PRACTICES

1. **Always Verify Schema**: Before writing queries, explicitly check the exact schema of the table using `\d tablename` or by reading the corresponding SQLAlchemy model.
2. **Migrations Only**: All Database changes go through `/backend/alembic/versions/`.
3. **Backup First**: Before proposing scripts that handle large data transformations, remind the user to run the backup script (`/data/docker-postgres/scripts/db_backup.sh`).

**Failure to comply with these database instructions could lead to severe data loss. Be conservative, explicit, and always ask for confirmation before performing data-mutating operations.**
